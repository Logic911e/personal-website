# The Computer (Photos and Chess) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aim at the monitor, press E, and a Windows 95-style desktop fills the window with a Photos app and a Chess app (Stockfish in the browser, three difficulty levels).

**Architecture:** The desktop is plain HTML/CSS laid over the room (like the project card), driven by small modules in `src/computer/`. Everything testable is a pure module in `src/lib/` (photos parsing, chess rules wrapper, difficulty settings, UCI parsing, fallback search, window clamping, clock). Stockfish runs in a Web Worker from vendored files and is created only when Chess is first opened. The room gains a generic "target" idea so the monitor and the notes are picked by the same raycast.

**Tech Stack:** Three.js (existing), Vite, Vitest, `chess.js` ^1.4.0 (BSD-2), `stockfish.js` 10.0.2 vendored (GPL-3.0; `stockfish.wasm.js` 97 KB + `stockfish.wasm` 559 KB).

**Spec:** `docs/superpowers/specs/2026-11-09-computer-design.md`

## Global Constraints

- Branch `build/computer` (already created, from `build/textures`). Run tests with `npx vitest run`; build with `npx vite build`.
- Only new runtime dependency: `chess.js` ^1.4.0. Stockfish is vendored in `public/assets/stockfish/` (files `stockfish.wasm.js`, `stockfish.wasm`, `Copying.txt`), never imported by the main bundle.
- The engine file must not be requested until the Chess window is first opened.
- Difficulty names are exactly `Easy`, `Medium`, `Hard`; visitor is always white; pawns auto-promote to a queen.
- The look is Windows 95: teal desktop `#008080`, grey `#c0c0c0` bevelled windows, navy `#000080` title bars, taskbar with Start button and clock.
- While the computer is open, the room is paused (no WASD, no E in the room); Esc or Start → Shut Down closes it and shows "Click to resume", exactly as the project card does.
- Text from data files (photo captions) is shown with `textContent`/escaping, never as raw HTML.
- Credit Stockfish (GPL-3.0) and chess.js in the README and a `THIRD-PARTY.md`.

## Review Focus

- A slow engine reply that arrives after New Game (or after a difficulty change mid-think) must never move a piece on the new game.
- Clicking a square while it is the computer's turn, or after the game is over, must do nothing.
- A missing/broken photo image, or an empty photo list, must not break the Photos window.
- The engine failing to load (or never answering) must fall back to the built-in search, and the game must still be playable.
- Typing or clicking inside the computer (dropdown, buttons) must never walk or act in the room; and Esc during engine thinking must still close the computer cleanly.
- Dragging a window must never leave its title bar unreachable off-screen.

### Task 4: Fallback search and UCI helpers

**Files:**
- Create: `src/lib/chessAi.js`, `src/lib/uci.js`
- Test: `tests/chessAi.test.js`, `tests/uci.test.js`

**Interfaces:**
- Produces (`chessAi.js`): `chooseMove(game: Chess, depth: number, rng = Math.random): { from, to, promotion? } | null` — alpha-beta search for the side to move, evaluation = material (P1 N3 B3 R5 Q9) plus a small piece-square bonus for knights/pawns toward the centre; picks randomly (via `rng`) among equally best moves; returns `null` when there are no legal moves. Does not mutate the passed game.
- Produces (`uci.js`): `parseBestMove(line: string): { from, to, promotion? } | null` — parses `bestmove e2e4`, `bestmove e7e8q ponder e2e4`; `null` for `bestmove (none)`, empty, or non-bestmove lines. `engineCommands(fen: string, settings: { skill, movetimeMs }): string[]` — exactly `["setoption name Skill Level value <skill>", "position fen <fen>", "go movetime <ms>"]`.

### Task 5: Engine wrapper with fallback

**Files:**
- Create: `src/computer/engine.js`
- Test: `tests/engine.test.js`

**Interfaces:**
- Consumes: `engineCommands`, `parseBestMove` (Task 4), `chooseMove` (Task 4), `levelSettings` (Task 3).
- Produces: `createEngine({ workerUrl: string, makeWorker = (url) => new Worker(url), loadTimeoutMs = 8000, moveTimeoutMs = 10000 }): { load(): Promise<boolean>, bestMove(fen: string, level: string): Promise<{ from, to, promotion? } | null>, dispose(): void }`. `load()` creates the worker only when first called, sends `uci`, resolves `true` on `uciok` (then `isready`/`readyok`), `false` on timeout or worker error. `bestMove` uses Stockfish when loaded and answering; on a worker error, an answer timeout, or no engine it falls back to `chooseMove(new Chess(fen), levelSettings(level).fallbackDepth)`. It never rejects. A reply is for the position it was asked about; callers drop stale replies (Task 6). `workerUrl` is injected so tests use a fake worker (an object with `postMessage`, `terminate`, and an assignable `onmessage`/`onerror`).
